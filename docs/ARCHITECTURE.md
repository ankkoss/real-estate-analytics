# System Architecture

## Architectural Style

Проект использует многослойную архитектуру (Layered Architecture).

Каждый слой отвечает только за свою задачу.

```
External Sources

↓

Ingestion Layer

↓

Raw Layer

↓

Validation Layer

↓

Staging Layer

↓

Warehouse Layer

↓

Data Marts

↓

API

↓

Dashboard
```

---

# Layers

## 1. Data Sources

Источники данных.

Примеры:

- ЦИАН
- Домклик
- Авито
- открытые API

Ответственность:

Предоставление сырых данных.

---

## 2. Ingestion Layer

Получение данных.

Компоненты:

- API Collector
- Scraper

Ответственность:

- загрузка данных;
- повторные попытки;
- логирование;
- сохранение RAW.

---

## 3. Raw Layer

Хранение необработанных данных.

Никаких изменений не производится.

Используется для:

- повторной обработки;
- аудита;
- восстановления.

---

## 4. Validation Layer

Проверка качества данных.

Примеры:

- отрицательная площадь;
- цена = 0;
- отсутствующий адрес;
- дубликаты.

---

## 5. Staging Layer

Подготовка данных.

Задачи:

- очистка;
- стандартизация;
- преобразование типов;
- объединение источников.

---

## 6. Warehouse Layer

Главное аналитическое хранилище.

Используется для SQL-запросов.

---

## 7. Data Marts

Специализированные витрины.

Например:

- цены;
- районы;
- история;
- инвестиционная аналитика.

---

## 8. API Layer

FastAPI.

Предоставляет данные Dashboard.

---

## 9. Dashboard

Интерактивная визуализация.

Показывает:

- KPI;
- карты;
- графики;
- тренды;
- фильтры.

---

# Principles

Архитектура строится на принципах:

- KISS
- SOLID
- DRY
- Separation of Concerns
- Single Responsibility

---

# Scalability

При увеличении объёма данных:

- можно добавить новые источники;
- заменить PostgreSQL на аналитическое хранилище;
- масштабировать ETL независимо;
- добавить новые Data Mart без изменения существующих.
